# 로드픽 · ROAD-PEAK

사이트 이름은 로드픽(ROAD-PEAK)이며 대표이미지는 운영자가 제공했습니다. 현재 글 4쌍은 화면 확인용 예시입니다. 첫 실제 원고 또는 주제는 운영자가 제공합니다. 상단은 큰 주제 메뉴와 검색창 하나로 구성했습니다. 참고 사이트의 글 목록·목차·표·FAQ 형식을 참고했으며 문장·사진·브랜드·소스는 복제하지 않았습니다.

## 현재 상태

- 독립된 새 작업 폴더입니다. 다른 프로젝트와 설정을 공유하지 않습니다.
- 광고·외부 추적·외부 글꼴·회원가입·댓글 수집 기능이 없습니다.
- 모든 본문·목차·카테고리는 초기 HTML에 포함됩니다.
- 검색 제외(`noindex`) 시안입니다. 공개 주소를 배포하면 URL을 아는 사람은 열람할 수 있습니다. `noindex`는 접근 제한이 아닙니다.
- 운영자 표시명은 로드픽, 공개 문의 이메일은 godwd25@gmail.com입니다. 소개·작성 기준·문의와 현재 기능에 맞는 개인정보·이용 안내를 제공합니다. 이메일 문의 보관 기준 등 남은 운영 방침은 정식 공개 전에 확인합니다.
- 개설 저장소: https://github.com/doyoung-rich/roadpick (공개). 대표 주소는 https://roadpick.store/ 이며 검색 제외 시안을 유지합니다. 광고·댓글 저장 기능은 연결하지 않았습니다.

## 글을 추가하는 방법

1. 한국어 글은 `content/articles/`, 영어 글은 `content/articles/en/`의 `.md` 파일로 저장합니다. 해당 언어의 예시 파일을 복사해 시작할 수 있습니다.
2. 파일명은 `new-guide.md`처럼 영문 소문자와 하이픈을 사용합니다. 이 이름이 주소에 들어갑니다.
3. 맨 위의 제목(`title`), 큰 주제 하나(`category`), 목록 설명(`description`), 첫 답변(`summary`)을 바꾸고 아래에 원고를 넣습니다. `category`에는 아래 주제 표의 공통 분류 코드 또는 기존 한국어 이름을 사용합니다. 세부 분류를 고를 필요가 없습니다. 예를 들어 보험 글은 `category: finance`, 공연 글은 `category: culture`입니다. 기존 `category: 금융`, `category: 문화`도 사용할 수 있습니다.
4. 실제 완성한 글은 `status: ready`로 바꿉니다. 숨길 원고는 `status: draft`로 둡니다. `sample`은 시안용입니다.
5. 실제 확인한 날짜가 있으면 `date: 2026-10-18`처럼 적습니다. 작성자 표시는 확인된 이름을 `author:`에 입력할 때만 표시됩니다. 예시 날짜를 실제 발행일로 사용하지 마세요.

의미 있는 본문 수정 날짜만 `modified: YYYY-MM-DD`로 추가합니다. 원래 `date`보다 빠른 날짜나 실제로 존재하지 않는 날짜는 빌드에서 차단됩니다. 수정일은 화면과 글의 검색용 설명 데이터에 함께 표시되며, 배포할 때마다 자동 갱신하지 않습니다. `status`는 `draft`, `sample`, `ready` 중 하나를 명시해야 합니다.

지원하는 본문 형식은 `## 소제목`, `### 작은 제목`, 일반 문단, `- 목록`, `1. 순서`, `**강조**`, 표, `[출처 이름](https://공식주소)`입니다. 임의 HTML은 표시하지 않습니다. 초기에 필요한 형식만 지원합니다.

원고를 채팅으로 전달해 수정·추가를 맡기는 방식도 가능합니다.

## 한국어·영어 글 운영

두 언어의 원고는 각각 저장하고 검토합니다. 언어 메뉴는 자동 번역 기능이 아니며, 해외 기사를 자동 수집하지도 않습니다. 한국어와 영어로 함께 제공할 글은 운영자가 검토한 별도 원고 두 개를 준비합니다.

- 한국어 주소는 기존 `/articles/파일명/`, 영어 주소는 `/en/articles/파일명/`입니다. 영어 홈페이지와 글 목록 등은 `/en/` 아래에 있습니다.
- 한국어 글은 `lang: ko`를 선택적으로 적고, 영어 글은 `lang: en`을 적습니다.
- 두 언어의 파일명이 같으면 같은 글의 언어별 원고로 연결됩니다. 파일명을 다르게 쓰고 싶다면 두 파일에 동일한 `translationKey`를 적습니다. 서로 다른 글에는 같은 `translationKey`를 쓰지 않습니다.
- 글에서 언어 메뉴를 누르면 해당 글의 다른 언어 원고로 이동합니다. 해당 원고가 없으면 선택한 언어의 전체 글 목록으로 이동하고 번역 글이 없다는 안내를 표시합니다.
- 검색 결과와 글 하단의 관련·추천 글은 현재 보고 있는 언어의 원고끼리 표시합니다.
- 문의·개인정보처리방침·이용약관은 영어에서도 준비 중 상태입니다. 운영 방식과 운영자 정보 확인 전에는 완성된 정책으로 취급하지 않습니다.

아래는 같은 글을 두 언어로 준비하는 예시입니다. 두 원고를 검토한 뒤에만 각각 `status: ready`로 바꿉니다. 예시 문장 자체는 발행용 정보가 아닙니다.

`content/articles/new-guide.md`:

```yaml
---
title: 새 안내 제목
lang: ko
translationKey: new-guide
category: living
description: 글 목록에 표시할 한국어 설명입니다.
summary: 독자에게 먼저 보여줄 한국어 답변입니다.
status: draft
keywords: 준비물, 이용방법
---
```

`content/articles/en/new-guide.md`:

```yaml
---
title: New guide title
lang: en
translationKey: new-guide
category: living
description: A reviewed description for the English article list.
summary: A reviewed answer to show at the beginning of the article.
status: draft
keywords: preparation, instructions
---
```

파일명이 같으므로 위 예시의 `translationKey`는 생략해도 됩니다. 제목·설명·첫 답변·본문·버튼 문구는 각 언어에 맞게 직접 작성합니다. 날짜는 실제 확인한 날짜만 `date: YYYY-MM-DD` 형식으로 추가합니다.

해외 기사에 기반한 원고는 사용 허락과 이용 범위를 확인하고 준비합니다. 원문 출처를 밝히는 것만으로 어떤 이용이든 가능하다고 전제하지 않습니다. 본문에 원문 링크와 필요한 경우 원문 발행일을 적고, 번역·편집한 글이라는 사실을 표시합니다. 현재 출처 링크는 별도 입력란 대신 본문에 `[원문 출처](https://확인한주소)` 형태의 Markdown HTTPS 링크로 넣습니다. 실제 확인한 출처와 허락 내용만 표시하며, 제공받지 않은 경험이나 검수 사실을 만들지 않습니다.

## 글 목록의 대표사진

홈페이지·전체 글·분야별 목록은 왼쪽에 대표사진, 오른쪽에 분류·제목·설명을 표시합니다. 휴대폰에서도 같은 배치를 유지합니다. 사진과 제목을 누르면 해당 글로 이동합니다.

1. 사용할 사진을 `assets/images/`에 넣습니다. 파일명은 영문·숫자·하이픈을 사용하고 WebP·JPG·PNG·AVIF 형식을 지원합니다.
2. 원고 맨 위에 `cover: assets/images/my-photo.webp`를 적습니다. 한·영 원고에서 같은 사진을 쓸 수도 있습니다.
3. 현재 예시 원고의 `coverSample: true`는 AI 시안 사진임을 표시합니다. 실제 사진으로 바꿀 때 이 줄을 지웁니다. 사용 가능한 사진인지 확인하고 필요한 출처·이용 조건을 함께 남깁니다.

대표사진을 지정하지 않으면 기존 분야별 기본 그림이 표시됩니다. 지정한 파일이 없으면 빌드를 중단합니다. 현재 사진 3장은 내장 이미지 생성 도구로 만든 시안용 예시이며, 실제 이용 경험·상품 시험·공연장 방문을 증명하는 사진이 아닙니다. [예시 사진 제작 기록](content/sample-image-notes.md)에 파일과 프롬프트를 남겼습니다.

## 글 검색 방법

사이트 위쪽의 검색창 하나로 현재 언어 글의 제목·목록 설명·첫 답변·본문·키워드·큰 주제를 검색합니다. 홈페이지와 전체 글 목록에서는 입력하면 결과가 바로 바뀌고, 다른 페이지에서 검색하면 해당 언어의 전체 글 검색으로 이동합니다. 여러 단어는 모두 들어 있는 글을 찾습니다. 검색어를 지우거나 '전체 글 보기'를 누르면 해당 언어의 전체 목록으로 돌아갑니다.

새 글을 추가하고 빌드하면 검색 자료도 자동으로 포함됩니다. 검색 목록이나 링크를 따로 등록할 필요가 없습니다. `keywords`는 선택 사항이며 본문만 올려도 검색됩니다. 검색에 JavaScript를 사용하지만, JavaScript가 없어도 전체 글 목록과 본문은 읽을 수 있습니다.

## 본문 중간에 큰 안내 버튼 넣기

원하는 문단 사이에 아래 블록을 넣습니다. 밝은 원형 화살표가 있는 둥근 보라색 버튼으로 표시되며 누르면 같은 탭에서 연결 페이지로 이동합니다. 버튼은 한 개 또는 여러 개 넣을 수 있습니다. JavaScript 없이도 작동합니다.

```text
:::cta
아래 버튼에서 다음 안내를 확인하세요.
[신청 준비사항 확인하기](/articles/application-checklist/)
[조건별 비교표 보기](/articles/service-guide/#section-2)
:::
```

첫 줄 안내 문장은 생략해도 됩니다. `[버튼에 표시할 문구](연결할 주소)`를 한 줄에 하나씩 적습니다. 사이트 안의 주소는 `/articles/.../`처럼 저장소 이름을 빼고 입력합니다. GitHub Pages의 저장소 경로는 자동으로 붙습니다. 외부 안내를 연결할 때는 직접 확인한 `https://` 주소를 입력합니다.

영어 글에서 영어 원고로 연결할 때는 `/en/articles/파일명/` 주소를 사용합니다. 예를 들어 `[Read the checklist](/en/articles/new-guide/)`처럼 적습니다. 같은 파일명이어도 영어 버튼의 목적지를 자동으로 번역해 바꾸지는 않으므로 연결하려는 언어의 주소를 직접 적습니다.

예시 원고의 버튼은 준비사항·비교표·예약 안내 예시와 글 목록으로 연결됩니다. 이 버튼 문구와 목적지는 실제 원고에 맞게 바꿉니다. 확인되지 않은 혜택이나 신청 페이지를 만들어 연결하지 않습니다. 내부 목적지나 지정한 소제목이 없으면 빌드를 중단해 깨진 버튼을 알립니다.

## 큰 글씨의 관련·추천 링크 버튼

첫 답변 아래·목차 위의 '다른 글도 읽어보세요'는 밝은 원형 화살표가 있는 큰 보라색 둥근 링크 버튼으로 표시됩니다. 작은 분류·설명 카드 대신 글 제목을 크게 보여주고, 다음 두 가지 방식으로 연결할 글을 선택합니다.

- 같은 주제의 글: 각 원고 맨 위에 `keywords: 신청, 준비물, 생활서비스`처럼 쉼표로 키워드를 선택적으로 적습니다. 겹치는 키워드가 많은 글을 먼저 보여주고, 같은 큰 주제의 글로 보완합니다.
- 추천 글: `content/site.json`의 `recommendedArticles` 배열에 추천할 글의 공통 `translationKey`를 순서대로 적습니다. `translationKey`를 생략한 글은 파일명에서 `.md`를 뺀 이름을 사용합니다. 같은 키에 연결된 원고 중 현재 언어의 글을 보여줍니다. 다른 분야의 글도 선택할 수 있으며, 원고를 실제로 준비한 뒤 해당 키를 넣으면 됩니다.

각 목록에는 현재 언어의 글을 최대 3편씩 표시합니다. 현재 읽는 글과 두 목록에 중복되는 글은 제외합니다. 추천 키에 해당하는 준비된 원고가 어느 언어에도 없으면 빌드를 중단해 설정을 확인하도록 알립니다. 한 언어에만 준비된 원고가 있으면 그 언어에서만 추천합니다. 조회수·인기도를 수집하거나 추정하지 않으며, 개인 추적도 사용하지 않습니다. 본문 중간의 큰 안내 버튼은 별도로 유지됩니다.

## 주제 분류 구성

세부 분류 없이 큰 주제만 사용하는 간단한 구성입니다.

| 한국어 메뉴 | 두 언어 공통 분류 코드 | 기존 한국어 이름 |
| --- | --- | --- |
| 생활정보 | `living` | 생활정보 |
| 금융 | `finance` | 금융·보험 |
| 문화 | `culture` | 문화·공연 |
| 여행 | `travel` | 여행·맛집 |
| 스포츠 | `leisure` | 스포츠·취미 |
| 정보 | `knowledge` | 지식·정보 |

기존 원고에 적힌 예전 세부 분류도 `content/site.json`의 `aliases`를 통해 큰 주제로 연결됩니다. 원고가 없는 분류는 '글 준비 중'으로 표시합니다. 다른 사이트의 콘텐츠·개인정보·광고 설정을 가져오지 않습니다.

## 컴퓨터에서 미리보기

Node.js 20 이상이 필요합니다. 추가 패키지 설치는 필요 없습니다.

```text
npm run build
npm run verify
npm run preview
```

미리보기 명령이 출력한 실제 로컬 주소로 확인합니다. 로컬 주소는 해당 컴퓨터에서만 열립니다.

## GitHub Pages 배포 준비

저장소를 만들기 전 계정·저장소 이름·공개 범위를 운영자에게 확인받습니다. 비밀키·환경설정 파일은 올리지 않습니다.

1. 확인받은 새 저장소에 이 폴더의 소스만 저장합니다. `dist/`는 자동 빌드되며 저장하지 않습니다.
2. 저장소 Settings → Pages → Source를 GitHub Actions로 선택합니다.
3. `main` 브랜치에 저장하면 포함된 워크플로가 HTML을 만들고 배포합니다.
4. Actions에서 빌드와 배포의 성공을 각각 확인하고, 실제 반환된 주소에서 메뉴·글·이미지를 확인합니다.

맞춤 도메인 https://roadpick.store/ 을 사용하므로 배포 워크플로의 BASE_PATH는 빈 값, SITE_URL은 해당 HTTPS 주소로 고정되어 있습니다. 도메인을 바꾸면 GitHub Pages 설정, DNS와 워크플로의 SITE_URL을 함께 수정해야 합니다.

설정 근거: [GitHub 공식 Pages 워크플로 안내](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

## 정식 공개 전

원고·브랜드·운영자·문의·개인정보처리방침·이용약관을 완성하고 운영자에게 공개 승인을 받습니다. 그 다음에만 `content/site.json`의 `preview`를 변경합니다. 정식 공개 상태에서도 예시 원고는 noindex를 유지하고 공개 목록과 사이트맵에서 제외합니다. 실제 대표 주소·사이트맵·검색 설정을 함께 확인해야 합니다.

승인·방문자 수·광고 수익은 보장하지 않습니다.

## 검색·공유 정보

- 실제 대표 주소의 canonical, 언어별 hreflang과 Open Graph·Twitter 공유 정보를 초기 HTML에 포함합니다. 한·영 원고가 모두 있을 때만 상호 언어 연결을 표시합니다.
- 홈에는 실제 사이트 이름을 설명하는 WebSite 데이터, 안내 페이지에는 목적에 맞는 페이지 데이터와 화면에 보이는 탐색 경로 데이터를 사용합니다. 실제 조직·전문가·평점은 만들어 넣지 않습니다.
- `status: sample` 글에는 BlogPosting 데이터를 넣지 않습니다. 준비가 완료된 글만 원고의 제목·설명·작성자·날짜를 사용합니다. 입력하지 않은 작성자나 날짜를 자동 생성하지 않습니다.
- `preview: true`에서는 noindex를 유지하고 sitemap을 배포하지 않습니다. robots.txt는 noindex를 읽을 수 있게 수집을 허용합니다. 정식 공개 승인 전에는 이 상태를 유지합니다.
- 검색을 허용한 뒤에도 빈 카테고리와 오류 페이지는 noindex이며 사이트맵에서 제외됩니다. 사이트맵의 lastmod는 실제로 입력한 글 날짜만 사용합니다.
- AI 검색용 특별 스키마나 llms.txt는 추가하지 않았으며, 학습 봇에 대한 별도 허용·차단 정책도 변경하지 않습니다.
- Search Console·네이버·Bing 소유 확인, 색인 여부와 실제 사용자 성능은 별도 계정과 데이터로 확인해야 합니다. 이 코드 검사를 검색 등록이나 노출 보장으로 해석하지 않습니다.

## 로드픽 브랜드와 공개 준비

- `content/site.json`에서 이름·대표이미지·운영자 표시명·문의 이메일을 관리합니다. 영문은 제공된 이미지의 ROAD-PEAK 표기를 사용합니다.
- 대표이미지: `assets/brand/roadpeak.webp`. 원본 구성을 보존한 웹용 파일이며, 헤더는 같은 이미지의 RP 부분을 화면에서 작게 보여줍니다.
- 소개·문의·개인정보·이용 안내는 `scripts/site-info.mjs`에서 현재 기능에 맞게 작성했습니다. 운영 방식이 바뀌면 함께 갱신합니다.
- 운영자가 첫 원고나 주제를 제공하기로 했으므로 임의의 신규 5편은 발행하지 않았습니다. `status: sample` 예시를 완성 원고와 바꾸고 사실·출처·권리·추가 가치를 사람 검토합니다.
- GitHub Pages 임시 배포 승인과 검색 허용 승인은 별개입니다. 2026-10-21 운영자 승인으로 `preview: false`로 전환했습니다. AdSense 연결·심사 요청은 하지 않습니다.

본문 PNG 이미지는 느낌표로 시작하는 Markdown 이미지 문법으로 assets/images/ 아래 파일을 지정합니다. 이미지 설명은 대체 텍스트와 캡션으로 표시되며 누르면 원본 크기로 열립니다. 손가락 버튼을 사용할 때는 CTA 시작 줄을 :::cta hand 로 입력합니다. 실제 발행 글의 관련 글에는 예시 글을 추천하지 않습니다.
